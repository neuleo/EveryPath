# EveryPath - Product Guidelines

## Tone and Voice
- **Professional & Sleek:** The application communicates with precision and modern authority. Avoid unnecessary fluff.
- **Bi-lingual:** All UI elements and documentation must be provided in both **English** and **German**. Use clear, unambiguous terminology (e.g., "Coverage" / "Abdeckung", "Route" / "Strecke").

## Visual Identity
- **High-Contrast Dark Mode:** The default and primary interface is a high-contrast dark theme. This ensures readability in outdoor conditions and provides a modern, sleek aesthetic.
- **Accents:** Use sharp, high-visibility colors (e.g., neon green or electric blue) for route overlays and "completed" path indicators.
- **Map Centric:** The map is the hero component. UI elements should be non-intrusive and semi-transparent where appropriate to maximize map visibility.

## UX Principles
- **Mobile-First Interaction:** While the dashboard is data-dense, all critical planning and viewing actions must be intuitive on touch screens. Buttons and toggles should be large enough for "active" use (e.g., during a run or bike ride).
- **Data-Dense Dashboard:** Provide comprehensive metrics (Distance, Elevation, % Coverage, Surface distribution) in a compact, collapsible sidebar or overlay.
- **Performance:** As a Docker-based app, ensure fast loading times and smooth map interactions (panning/zooming) even with large polygon datasets.

## Content Standards
- **Clarity over Cleverness:** Use industry-standard terms for routing and mapping.
- **Precision:** Ensure that mathematical terms (e.g., "CPP", "Eulerian Path") are used correctly in technical documentation.
